Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talking to a Python FastAPI service that serves in-memory mock data loaded from JSON files. There is no database, no auth backend, and no persistence.

Data Flow: Applying a Filter

What happens when a user changes a filter in the FilterBar (e.g. Warehouse = "San Francisco", Period = "Q2-2025").

FilterBarUser picks a value; it writes to a shared ref in useFilters.
Singleton stateRefs live at module scope, so every view sees the same filter values.
View reloadsThe view watches filters and calls getCurrentFilters() then api.*().
api.jsDrops any value equal to 'all' and builds a query string.
FastAPIapply_filters (warehouse, category, status) then filter_by_month (month or quarter).
RenderResponse validated by Pydantic; Vue computed properties derive KPIs and charts.

Filtering rules on the server

  • Warehouse is an exact match; category and status are case-insensitive.
  • Month accepts YYYY-MM or a quarter key like Q2-2025, expanded via QUARTER_MAP. Matching is a substring check on order_date.
  • Inventory ignores status and month; it has no time dimension.
  • Demand, backlog, spending, reports are not filtered at all.
  • /dashboard/summary filters inventory and orders separately, then aggregates value, low stock, and pending counts.

Components

  • FilterBar: global filters
  • ProfileMenu, ProfileDetailsModal
  • LanguageSwitcher: en / ja
  • TasksModal: to-do list
  • Detail modals: Inventory, Product, Backlog, Cost

Composables & utils

  • useFilters: module-level refs shared app-wide
  • useI18n: translations from locales/en.js, ja.js; locale saved to localStorage; currency follows locale (USD / JPY)

Observations

Things worth knowing before you change the code.

Gaps between client and server

  • api.js calls /api/tasks and /api/purchase-orders, which main.py does not implement. The Tasks modal and purchase order creation will get 404s.
  • PurchaseOrder and CreatePurchaseOrderRequest Pydantic models exist with no endpoint using them.
  • Reports.vue calls axios with a hard-coded URL instead of going through api.js.
  • Backlog.vue is not registered in the router.
  • The API base URL (http://localhost:8001/api) is hard-coded; there is no Vite proxy or env variable.
  • Quarters are hard-coded to 2025 in both QUARTER_MAP and /reports/quarterly.
  • Responses for /dashboard/summary, /spending/* and /reports/* have no Pydantic response model.
